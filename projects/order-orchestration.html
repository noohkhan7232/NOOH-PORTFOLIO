Problem Statement & Architecture Solution

In distributed e-commerce environments, traditional monolithic ACID database transactions fail across microservices boundary limits. When an order is placed, payments, inventory reservation, and shipping allocation must execute reliably without locking databases or stranding orders in partial state failures.

The Solution: Built an event-driven order orchestration system using Python and FastAPI. Implemented an **Orchestrated Saga Pattern** where a central coordinator emits state events to message queues (RabbitMQ/Redis Stream). If payment or inventory validation fails at any point, compensating transactions are automatically dispatched to revert prior operations deterministically.

Core System Features

  • Saga Pattern Coordinator: Manages state transitions for order creation, stock lock, payment authorization, and order confirmation.
  • Compensating Transaction Engine: Guarantees eventual consistency by executing rollback commands (e.g., releasing reserved inventory if payment times out).
  • Idempotent API Handlers: Enforces unique transaction keys in Redis to safely prevent duplicate order submissions during network retries.
  • Async I/O Event Loop: Leveraged Python `asyncio` and `aio-pika`/`redis-py` for non-blocking message processing under high concurrency.
  • PostgreSQL Database Isolation: Utilized SQLAlchemy 2.0 async sessions with strict transaction isolation levels.
